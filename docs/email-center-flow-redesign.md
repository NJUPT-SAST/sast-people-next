| 项目 | 内容 |

| 版本 | v1 |

| 实现入口 | `/dashboard/emails` |

## 1. 问题诊断

当前邮件中心把三类职责平铺成五个同级页签：

1. **业务动作**：发招新结果通知（管理员主动操作）
2. **运维查询**：发送记录、失败重试
3. **平台配置**：模板文案、SMTP/就绪检查

面试邮件是**业务事件驱动**（预约/改约/取消后自动投递），不在邮件中心发起。  
若把「发结果通知」和「面试通知」在心智上并列，管理员会误以为面试也要在这里群发，链路混乱。

平台能力层（单一出口、delivery 为事实源、快照不可变、失败可恢复）已在 `email-center-design.md` 中定义且 largely 落地；本文件只重定 **产品信息架构与主链路**，不改发送内核。

## 2. 产品定位（Option A：业务工作台）

邮件中心是管理员完成「招新结果邮件」与「全站邮件追踪」的工作台，不是 SMTP 控制台。

| 优先级 | 能力 | 页签 |
| --- | --- | --- |
| P0 | 给通过/不通过名单发结果通知 | **发结果通知**（默认落地） |
| P0 | 查某封是否发出、失败原因、重试 | **发送记录** |
| P1 | 改结果/面试文案、测试发送 | **模板管理** |
| P2 | 看今日指标、失败关注点、运行配置 | **系统状态**（合并原概览+配置） |

### 非目标

- 不在邮件中心提供「发起面试通知」入口（面试由预约流程自动触发）
- 不在页面编辑 SMTP 密钥/环境变量（只读展示）
- 业务模块（成绩管理、面试预约）不直连 SMTP

## 3. 三条主链路

### 3.1 结果通知（主动、批量）

```text
成绩管理：标记 通过 / 不通过
    → 邮件中心「发结果通知」
        → 选流程（可从招新深链 ?tab=tasks&flowId=）
        → 分别对「通过 / 不通过」名单预览 → 确认发送
        → 批次入队 / delivery 落库
    → 需要核对或失败时 →「发送记录」筛选 / 重试
```

不变量：

- 同一用户同一结果类成功投递不重复发（现有业务规则保持）
- 发信前保存 subject + htmlSnapshot

### 3.2 面试通知（事件驱动、单封）

```text
预约 / 改约 / 取消
    → 业务只提交邮件请求（变量 + 关联 ID）
    → 邮件中心投递 + 记录
    → 管理员仅在「发送记录」查询；文案在「模板管理」维护
```

### 3.3 测试发送

```text
模板管理 → 测试发送 → category=test 的 delivery → 发送记录可查
```

## 4. 页面职责

### 4.1 发结果通知（`tab=tasks`，默认）

- 左：流程列表（搜索、待发计数）
- 右：当前流程的通过/不通过两条发送道
- 下方或侧：本流程相关批次状态（发送中、失败恢复）
- 不展示面试「去发送」入口

### 4.2 发送记录（`tab=records`）

- 全品类（result / interview / test）统一列表
- 筛选：状态、品类、流程、时间、关键词
- 操作：预览快照、重试（允许时）、跳转业务对象

### 4.3 模板管理（`tab=templates`）

- 分组：**招新结果** / **面试通知**
- 每组：编辑变量默认值、预览、测试发送
- 文案说明：面试在业务侧自动发，这里只改文案

### 4.4 系统状态（`tab=status`）

合并原「概览」+「配置」：

- 今日发送 / 失败 / 进行中
- 需关注的失败摘要 → 链到记录
- 最近批量任务 → 链到发结果通知
- 只读运行配置与上线前检查

兼容：旧链接 `tab=overview` / `tab=config` 归一到 `status`。

## 5. 导航与文案

页眉说明（用户可见主句保留 e2e 标记前缀）：

> 统一管理系统邮件模板、发送任务和发送记录。结果通知在这里发送，面试邮件由预约自动发出。

默认：`/dashboard/emails` → `tasks`。  
推荐深链：`/dashboard/emails?tab=tasks&flowId={id}`。

## 6. 与旧设计文档关系

| 文档 | 角色 |
| --- | --- |
| `email-center-design.md` | 平台边界、类型、数据、不变量（仍有效） |
| 本文 | **面向管理员的主链路与 IA**；覆盖旧文档 §5 的五 tab 平台控制台布局 |
| `email-center-implementation-status.md` | 实现完成度（发送/重试/hardening） |

若冲突：用户可见 IA 以本文为准；发送内核与不变量以 design + 现网代码为准。

## 7. 实现分期

1. **IA / 路由**：默认 tasks、四 tab、overview/config 兼容、flowId 深链（本轮）
2. **入口串联**：成绩管理成功后提供「去发结果通知」深链
3. **文案收敛**：去掉面试可群发的暗示；空状态指向正确下一步
4. **发送内核**：无需求不改；仅在契约/ bug 时动

## 8. 验收

- 无 tab 参数进入时默认在「发结果通知」
- `?tab=overview` / `?tab=config` 落到「系统状态」
- `?tab=tasks&flowId=` 预选对应流程（存在时）
- e2e：管理员可打开邮件中心并看到导航与页眉主句
- 本地：管理员（seed `001`）可走「选流程 → 预览 → 发送 → 记录可见」
